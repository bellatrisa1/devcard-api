## Docker-проверка 27.10.2026

Использованы Docker Desktop 4.97.0, Engine 29.9.2 и Compose 5.6.1. Отдельный проект `devcard-acceptance-20261027-1730` получил свой новый volume, сеть и loopback-порт 33045. Существующая локальная PostgreSQL и пользовательские контейнеры/volumes не затрагивались.

Запуск выполнен с `.env.example`, без использования локального DATABASE_URL. Приложение дождалось PostgreSQL healthcheck, применило одну миграцию, выполнило seed и стало healthy. База осталась только в Compose network.

Проверено содержимое production image: compiled JS и Prisma Client, Prisma CLI, schema/config, миграция и seed доступны; runtime UID не 0; `.env`, `.local`, eslint и tsc-watch отсутствуют. Для запуска не понадобились dev-зависимости.

После restart приложения выполнен полный запрос: ответ совпал с исходным, количества остались `1/27/27/2/7/3`. У работ 3 и 4 достижения, даты — YYYY-MM, неизвестные repositoryUrl — null.

Остановлена только БД acceptance-проекта: live вернул 200, ready — 503 с безопасным ответом. После запуска БД ready вернулся к 200. Затем приложение остановлено с таймаутом 15 секунд: нет SIGKILL/OOM, соединений приложения в PostgreSQL не осталось. Приложение снова запущено и проверено.

Браузерный прогон Playwright/Chromium открыл контейнерный `/graphql`, загрузил Sandbox и схему. Точный запрос работодателя введён в редактор и выполнен кнопкой Run. JSON без errors отобразился в UI: Белла Манкиева, 27 навыков, Буше → МКБ, Orbit → Lexora → Event Form Flow App.

### Исправления по результатам реального запуска

1. В `.dockerignore` добавлены `.local` и `.DS_Store`: локальный PostgreSQL и служебные файлы не должны попадать в Docker context.
2. Первая сборка выявила неполную запись транзитивного `@graphql-tools/utils` в lockfile: npm из Node 24 отклонил `npm ci` с EUSAGE. Lockfile согласован в отдельном контейнере с npm 11.12.1 из выбранного образа. Прямые версии зависимостей не менялись. После этого `npm ci`, сборка и production prune в Docker прошли.
3. Docker CLI/credential helper были установлены в пользовательский каталог, не видимый старому терминалу. Для проверки PATH настроен только у текущих процессов; shell-конфигурация пользователя не менялась.

Дополнительно на локальном Node 22 проверены исправленный lockfile через `npm ci`, lint и 3 HTTP/конфигурационных теста. Первый локальный `npm ci` столкнулся с ENOTEMPTY при очистке node_modules; повторная установка прошла. Audit при успешной установке и production prune сообщил 0 уязвимостей.

## Предыдущие PostgreSQL-проверки

- Build, lint, Prisma validate, Prettier и 3 HTTP/конфигурационных теста проходили.
- Две DB-интеграции создавали собственные случайно названные БД и удаляли только их в finally. Проверялись чистая миграция, повторяемость seed, сохранение посторонних записей, откат при конфликте, точный/полный query, порядок и nullable поля.
- Тестовое SQL-инструментирование показало 6 statements на исходных данных и 6 после добавления 20 работ и 200 достижений; в обычных логах SQL/параметры не выводятся.
- Production-only установка вне Docker также проверялась. Ошибки миграции и seed блокировали HTTP startup с ненулевым выходом и безопасным сообщением.
